# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Stow-managed dotfiles for an XPS laptop running omarchy (Hyprland/Wayland). The repo uses GNU Stow with `--no-folding` to symlink config files into `~` and `~/.config`.

## Layout

Two stow roots with different targets:

- **`home/`** — per-app packages (`zsh`, `bash`, `misc`, `claude`, `bin`), each stowed into `$HOME`
- **`config/`** — single stow package stowed into `~/.config`
- **`_archive/`** — old configs kept for reference, not stowed

## Commands

```bash
just install      # symlink everything
just uninstall    # remove symlinks
just reinstall    # prune stale + restow
just adopt        # first-time: adopt existing files into the repo
just check        # dry-run all packages; fails if any package conflicts
just list         # list packages
```

## Key details

- Stow runs with `--no-folding` — individual files are symlinked, not directories. This matters when adding new files: the directory structure in the repo must mirror the target.
- `config/nvim/` is a LazyVim config; `lazy-lock.json` is gitignored (auto-generated by lazy.nvim).
- Omarchy v4: Hyprland config is Lua (`config/hypr/*.lua`, entry point `hyprland.lua`); `hypridle`/`hyprlock`/`hyprsunset`/`xdph` remain `.conf`. The bar/notifications are the Quickshell-based omarchy shell (`config/omarchy/shell.json` + `shell.toml`), not waybar/mako. Shell bar-widget plugins (QML + `manifest.json`) live in `config/omarchy/plugins/` and are tracked in the repo.
- Omarchy is installed at `/usr/share/omarchy`; `~/.local/share/omarchy` currently links there. Theme state lives in `~/.local/state/omarchy/` — neither is tracked here. `~/.config/hypr/.luarc.json` is omarchy-generated and untracked.
- Pre-v4 configs (hypr `.conf` files, waybar) are in `_archive/pre-v4/`.
- Four files are **snapshots, not symlinked** — their writers replace the live file via atomic rename (which destroys a symlink), so `.stow-local-ignore` files exclude them from stow, and the repo copy is resynced manually with `cp` after an intentional change:
  - `config/omarchy/shell.json` + `shell.toml` — rewritten by the omarchy shell when bar settings change (`cp ~/.config/omarchy/shell.{json,toml} config/omarchy/`)
  - `config/alacritty/alacritty.toml` — regenerated by omarchy theme-set (`cp ~/.config/alacritty/alacritty.toml config/alacritty/`)
  - `home/claude/.claude/themes/omarchy.json` — rewritten by `omarchy-theme-set-claude` on every `omarchy theme set` (`cp ~/.claude/themes/omarchy.json home/claude/.claude/themes/`)

  Note `.stow-local-ignore` replaces stow's default ignore list, so it must keep the `\.git`/`\.gitignore` entries.
- `omarchy update`/`refresh` can silently reset live configs under `~/.config/omarchy/` back to stock as plain files, breaking stow links and dropping customizations (this has hit `shell.json` and `extensions/omarchy-menu.jsonc` before). After any omarchy update, run `just check`; treat "neither a link nor a directory" conflicts as a signal to diff the live file against both the repo copy and the stock package version to decide which side wins.
- `home/claude/` tracks `~/.claude` as a strict whitelist (settings.json, statusline-command.sh, CLAUDE.md, themes/omarchy.json). The root `.gitignore` blocks everything else under it — credentials, history, sessions, caches must never be committed. Skills in `~/.claude/skills/` are symlinks to their own repos and are not tracked here.
- The `omarchy` skill should be used when editing desktop/WM/system configs (hypr, omarchy shell, walker, ghostty, alacritty).
- `README.md` documents the full tracked/not-tracked inventory and external dependencies. Notable gotchas from it: the `hyprland-scroll-overview` plugin behind `SUPER+W` is managed by hyprpm (state in `/var/cache/hyprpm/$USER`, invisible to config greps; needs `hyprpm update` after Hyprland updates), and the hand-written `~/.local/bin` helpers `bindings.lua` references are tracked as the `home/bin/` stow package.
